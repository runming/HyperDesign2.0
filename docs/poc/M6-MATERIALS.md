## 三、量化成效：新增「表 3 分环节耗时账」

| 环节 | 1.0 实测 | 2.0 实测 | 变化原因 |
|---|---|---|---|
| 向量模型冷启动（一次性） | 176.6s | 同（可常驻） | 冷启动成本不变 |
| 工艺规范检索与铁律校验 | 75.9s（整段大模型推理） | 0.02s 检索 + 毫秒级规则判定 | 改为混合检索 + 规则引擎 |
| 概念图提示词生成 | 160~182s | 同 | 沿用生成式链路 |
| 4 张概念图生成 | 554s（≈138.5s/张） | 同 | GPU 主导，当前总耗时瓶颈 |
| 三维重建（TRELLIS） | 17~32s | 同 | 沿用 |
| 白模清洗与毫米对齐 | 9s | 同 | 沿用 |
| 参数化建模 + 几何校验 | **465.8s**（每次运行都要重新生成代码） | **2.5s**（中间表示构建 + 两道准入 + 仿真 + 审批） | 改为「一次规划、多次确定性执行」 |
| 工程图（A3 DXF + 300dpi PDF） | 12s | 同 | 沿用 |
| 端到端合计（不含冷启动） | ≈21.6 分钟 | ≈13.8 分钟（**减少 36%**） | 主要来自建模与校验环节的确定性化 |

> 数据全部取自 `progress.log` 与 2.0 工作流事件流时间戳，可复算。
> 诚实说明：总耗时仍由生成式环节（概念图 554s）主导；2.0 的收益集中在「建模—校验」段——
> 465.8s → 2.5s，且结果可复现（两次重建体积偏差 0.0000%），而 1.0 每次重跑都要重新生成代码。
