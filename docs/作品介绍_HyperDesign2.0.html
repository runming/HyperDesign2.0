一、为什么需要 2.0：1.0 的三个结构性缺口

1.0 版证明了「概念图→白模→参数化实体→国标图纸」可以端到端跑通，但作为参赛与交付系统，它有三个硬伤：

缺口1.0 的问题2.0 的解法
执行不可审计由大模型直接生成建模脚本并在几何内核里执行——不可复现、换不了内核，且存在任意代码执行风险受控几何中间表示（IR）：模型只产出 JSON，执行体是固定白名单解释器，execute_script 一律拒绝
结论不可追溯可制造性检查是硬编码判断，只有布尔结论，说不出"哪条规范、实测多少、差多少、怎么改"准入规则引擎：规则携带规范文档与条款原文、实测值/限值/单位、整改建议与阻断语义
过程不可观测线性脚本 + 文本日志，没有阶段状态、没有审批门、失败无法定位到节点工作流引擎：持久化 DAG、单调序号事件流、SSE 推送、人工审批门、断点续跑与幂等

补充两个能力缺口：1.0 没有仿真（无法回答"够不够强"），也没有知识资产（工艺规范写死在代码里）。2.0 一并补齐：自研有限元求解器与支持角色隔离的知识库。

3.1 端到端链路（6 节点工作流）

① 几何中间表示构建 → ② CAD 几何准入（B-Rep 合法性 / 三向包络 / 基准面 / 实测拔模）→ ③ 网格物理准入（射线测厚 p10 / 拔模场 / 水密 / 包络漂移）→ ④ 数值仿真（导光孔应力集中）→ ⑤ 仿真准入（结果是否已对标 / 应力区间 / 许用值）→ ⑥ 人工验收门。任一层判失败或无效，后续节点与审批门立即阻断。

四、四个真实应用场景

① 注塑结构件敏捷开发
输入功能描述与包络，自动注入企业规范（壁厚 2.4mm / 筋 1.44mm / 拔模 1.8°），产出通过几何校验的 STEP 与 A3 工程图。
实测：首轮通过，包络偏差 0，体积 69,042.2mm³
② 钣金与激光切割件排产
自动剥离图框与尺寸线，输出 1:1 纯净外轮廓与孔位的激光切割文件。
实测：TOP 轮廓 82 条，仅切割图层
③ 非标零部件系列化派生
交付参数化几何中间表示而非死模型，改参数即派生同族规格，图纸与工艺约束同步。
实测：两次重建体积偏差 0.0000%
④ 跨部门免插件协同审阅
零构建单页，浏览器内三维旋转、线框检查、Z 轴剖切、包络核对与一键提交。
实测：一次提交归档 3 条偏好样本

五、六个创新点

  1. 几何真实优先的跨模态尺寸锚定：以白模三层高度（10%/50%/90%）截面采样作为草图尺寸锚点，把美学比例翻译为可校验的尺寸约束，最终实体包络与目标偏差为 0。
  2. 受控几何中间表示 + 自愈闭环：模型只产出数据、不执行代码；内核返回拓扑/体积/包络误差作为硬判据，失败回传诊断并最多自愈五轮，失败与成功样本同时进入偏好数据。
  3. 客观物理信号优于视觉评分的三级评判：射线测厚与拔模场作为第一关，通过后才进入视觉语言模型评分与人工终审；白模因薄壁 1.51mm、拔模 0.84°、非水密被判不通过，系统改走"白模仅作锚点、实体按铁律重建"路径。
  4. 工艺知识、规则与证据一体化：每条规则裁决都带文档、条款原文、实测值与建议动作；知识检索设证据门控，无证据即拒答，把"凭印象回答"改造成"凭证据裁决"。
  5. 自研数值仿真并强制对标：无外部求解器依赖，梁单元对等截面梁为精确解（误差 0.0000%），带孔板应力集中与经典解误差 4.25%；未通过对标的结果不得作为设计依据。
  6. 零边际成本的偏好进化与守门员：设计选择与自愈记录自动成为偏好样本；模型迭代必须通过黄金基准回归，未全面超越即禁止切流（实测样本不足时守门员判定 0/1，正确阻止上线）。

七、落地可行性

  • 单机离线：一张 16GB 消费级显卡 + Windows/WSL 双环境，全部推理与几何计算本地执行，断开外网可完整运行，无云端 API。
  • 零构建前端：交互层为静态单页（本地 vendored 三维库），无 npm 构建链，拷走即用。
  • 标准格式交付：STEP / DXF / PDF 直接进入既有 CAD、CAM 与质检流程，不改变企业现有工具链。
  • 数据合规：文档与资产不出内网；知识库按角色隔离；运行产生带序号的审计事件；产物下载做文件名白名单与路径规范化；智能体工具调用采用允许列表。
  • 可复制性：换行业只需替换知识文档与规则包，不改代码；所有门禁脚本可复跑，验收标准客观。

八、已知限制（如实披露）

  1. 生成式白模本身不可直接制造：单图重建的网格不水密、壁厚与拔模不可控，系统将其降级为"造型比例参考"，制造实体由受控建模按工艺铁律重建——这正是三级评判存在的意义。
  2. 偏好进化需要样本量：本次仅 3 条偏好样本做机制验证，进化模型在基准题上一通过率为 0/1，守门员据此禁止切流；按规范需积累 50~100 条再做正式进化。
  3. 部分规划组件在本机不可用：建模库的原生扩展无法加载，改用同一开源几何内核的宿主程序；检索与求解改为自研实现。替换原因与验证结果逐条记录在仓库 issues.md（24 条）。
  4. 市场与成本数据尚缺第三方核验：材料中的市场判断为定性分析，量化收益需在试点客户处标定后再补充。
